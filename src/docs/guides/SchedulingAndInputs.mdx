# 일정·입력

날짜·일정·보드·입력 유형 컴포넌트의 선택 기준입니다. Base UI에는 공개 달력 컴포넌트가 없어(1.9 기준) 달력·날짜 선택·타임라인·칸반은 yorha가 직접 만듭니다. 외부 날짜·차트 라이브러리는 쓰지 않으며 칸반만 `@dnd-kit`을 씁니다.

## 달력과 날짜 선택

- [Calendar](?path=/docs/컴포넌트-날짜-calendar--docs): `Date`와 `Intl`만 사용하는 WAI-ARIA 날짜 격자입니다. `mode`는 `single`, `range`. `minDate`, `maxDate`, `isDateDisabled`, `numberOfMonths`, `locale`(기본 `ko-KR`), `weekStartsOn`(기본은 로케일의 주 시작 요일)을 지원합니다.
- 키보드: 화살표(일·주 이동), PageUp/PageDown(월), Shift+PageUp/PageDown(해), Home/End(주의 처음·끝), Enter/Space(선택). 선택할 수 없는 날은 건너뜁니다. 날짜 칸의 이름은 일 숫자이고, 월·요일 문맥은 격자 이름과 열 머리글에서 옵니다.
- [DatePicker·DateRangePicker](?path=/docs/컴포넌트-날짜-datepicker--docs): 입력란에 직접 쓰거나 "달력 열기" 버튼으로 팝오버 달력을 엽니다. 입력은 블러·Enter에서 로케일 순서, ISO, 숫자 8자리를 해석하고 형식이 틀리면 "날짜 형식" 오류를, 선택할 수 없는 날이면 "선택할 수 없는" 오류를 보여 줍니다. Esc나 날짜 선택으로 닫으면 포커스가 버튼으로 돌아옵니다. 범위는 끝 날짜를 고르면 닫힙니다.
- 날짜만 한 칸에 받을 때는 [DateInput](?path=/docs/컴포넌트-폼-dateinput--docs)(`date`, `datetime-local`, `month`, `week`, `time`)을 씁니다. `type="date"`는 선택적으로 달력 팝오버를 붙일 수 있습니다.

## 타임라인

[Timeline](?path=/docs/컴포넌트-데이터-timeline--docs) 문서에 두 컴포넌트가 있습니다.

- `TimelineGraph`: 레인별 막대(시작+끝)와 마름모(시점), 현재 시각 선, 의존선을 SVG로 그립니다. x 좌표는 시간에 선형 비례하며 `hour`, `day`, `week` 눈금(64/96/128px)과 확대·축소(+/- 키, 버튼)를 지원합니다. 모든 항목이 키보드로 접근되며 화살표 순서가 시간 순서입니다. "표" 보기로 바꾸면 같은 항목을 시간순 표로 보여 주므로 차트를 읽기 어려운 사용자가 같은 정보를 얻습니다.
- `Timeline`(세로): 이벤트 로그용 목록입니다. 상태(`info`, `success`, `warn`, `danger`)는 색 외에 점 모양과 화면 낭독용 글자로도 전달됩니다.

## 칸반

[Kanban](?path=/docs/컴포넌트-yorha-kanban--docs)은 `KanbanBoard`에 `columns`와 `onChange`를 줍니다. 카드·열 id는 보드 안에서 유일해야 합니다.

- 카드마다 "이동" 핸들 버튼이 유일한 드래그 시작점입니다. 키보드는 Space/Enter로 집고, 화살표로 옮기고, Space로 놓고, Esc로 취소합니다. `onChange`는 놓았을 때 순서가 바뀐 경우에만 한 번 호출됩니다.
- 안내 방송은 한국어이므로 래퍼에 `lang="ko"`를 둡니다. 열의 `wipLimit`을 넘으면 개수가 경고색과 삼각형 글리프로 바뀌고 안내 방송이 나옵니다(줄이 늘지 않습니다). 보드 가장자리 48px에서 자동 스크롤되며, `collapsible`로 열을 접을 수 있습니다.
- 포인터·터치 드래그는 자동 테스트가 없습니다(키보드 이동만 검증, [UX 감사](?path=/docs/가이드-ux-접근성-감사--docs) 참고).

## HTML input 22종

<code>input</code>의 <code>type</code> 값 22개를 어느 항목이 맡는지 정리한 표입니다. 표는 <code>input-types</code> 항목의 <code>INPUT_TYPE_TABLE</code>에서 읽습니다. 전체 갤러리는 [InputTypes 스토리](?path=/story/컴포넌트-폼-inputtypes--all-input-types)에서 봅니다.

  <thead><tr><th scope="col">type</th><th scope="col">항목</th><th scope="col">구현 방식</th></tr></thead>

    {INPUT_TYPES.map((type) => (
      <tr key={type}><td><code>{type}</code></td><td><code>{INPUT_TYPE_TABLE[type].item}</code></td><td>{INPUT_TYPE_TABLE[type].how}</td></tr>

  </tbody>
</table>

- `text`, `email`, `tel`, `url`은 `inputPresets`를 펼쳐 올바른 키보드(`inputMode`)와 자동완성(`autoComplete`)을 얻습니다: `<Input {...inputPresets.email} />`. `tel`의 `pattern`은 느슨하므로 지역에 맞게 조입니다.
- `number`는 Base UI NumberField가 `type=text`를 렌더하므로 숫자 키패드가 필요한 곳에는 `Input type="number"`를, 스테퍼가 필요한 곳에는 NumberField를 씁니다.
- `password`: 표시 토글(`aria-pressed`, 이름 "비밀번호 표시")과 Caps Lock 안내. `search`: 지우기 버튼, Esc로 지움. `file`: 버튼과 드롭 영역, `accept`·`maxSize` 검사. `color`: 견본과 16진수 입력.
- `hidden`은 UI도 레이블도 없는 일반 `<input type="hidden">`입니다.

## v3 입력 마이그레이션 노트

- **높이는 명시적 스케일**: 텍스트 입력·비밀번호·검색·숫자·색상은 모두 `h-control-md`(기본 48px)이고 `fieldControlClass`를 공유합니다. 스토리나 소비 코드의 `h-9`·`h-10` 같은 임의 높이 덮어쓰기는 지우세요(`Fieldset` 안의 `FieldControl`도 마찬가지). 크기를 바꾸려면 `h-control-sm`/`h-control-lg`만 씁니다.
- **FormSubmit**: 이제 공유 `Button`(`variant="primary"`, `type="submit"`)입니다. 받는 props는 `ButtonProps`에서 `variant`·`type`을 뺀 것(`size`, `loading`/busy, `disabled` 등)이며, 독자 스타일 클래스에 의존하던 코드는 `className`으로만 조정하세요.
- **Textarea `resize`**: 기본은 `resize-none`입니다. 브라우저 세로 그립이 필요하면 `resize` prop을 켜세요. 높이는 `rows`를 따르고 `max-h-64`에서 스크롤합니다.
- **NumberField**: `description`과 `error` prop이 생겼습니다. `error`를 주면 필드가 invalid가 되고 메시지가 `FieldError`로 연결됩니다. 내부는 `Field` + `InputGroup`이라 포커스 링은 프레임 하나입니다. 별도 `Field`로 감싸 메시지를 달던 코드는 prop으로 옮기세요.
- **OTPField**: 슬롯은 정사각형(`w-control-md`)이며 줄어들 때 `aspect-square`로 따라갑니다. 6칸이 소수 픽셀에 걸리지 않으려면 컨테이너를 336px 이상으로 두세요.
- **FileInput**: 드래그 중 안내와 거부 사유(`FieldError`)가 드롭존 아래에 표시됩니다. 파일 행은 이름(말줄임, `title`) · 크기 · 제거 순입니다.
